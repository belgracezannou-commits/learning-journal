# \# Semaine 1



## \## Ce que j'ai appris



##### \### La théorie



J'ai découvert la différence entre \*\*Git\*\* et \*\*GitHub\*\*.



\*\*Git\*\* est un logiciel qui garde l'historique de mon projet. À chaque étape importante, je fais une sauvegarde, comme une photo du projet à un instant donné, avec un message qui explique ce que j'ai modifié. Cette sauvegarde se fait sur mon ordinateur.



Mes projets sont rangés dans des \*\*repos\*\* (repositories) : un repo, c'est le dossier d'un projet.



\*\*GitHub\*\*, quant à lui, c'est un site web qui stocke en ligne mes projets et tout leur historique. Ça me permet de les partager avec des recruteurs ou d'autres personnes : ils peuvent voir mes projets en mode observateur, sans pouvoir les modifier.



Le terme \*commit\* désigne une sauvegarde dans l'historique. C'est la sauvegarde à chaque étape dont j'ai parlé plus haut.



Une fois mes commits faits :

\- je les envoie en ligne sur GitHub avec un \*\*push\*\* ;

\- je récupère la version en ligne sur mon ordinateur avec un \*\*pull\*\*, par exemple si j'ai modifié un fichier directement sur le site.



Une \*\*branch\*\* (branche) sert à tester quelque chose sans toucher à la version principale du projet, la branche `main`. Si le test me plaît, je l'ajoute ensuite à la version principale.



Le \*\*README\*\* est la page de présentation d'un projet : c'est la première chose qu'on lit.



##### \### La pratique



###### \*\*1. Création de mon premier repo\*\*



Sur le site GitHub, j'ai créé mon repo `learning-journal` :

\- Name : `learning-journal` (sans espaces ni accents)

\- Description : « Mon parcours d'apprentissage en data analyse »

\- Add README : activé, sinon le repo est vide

\- Visibility : Public, puisque c'est mon journal d'apprentissage



Ensuite, j'ai créé ce fichier avec \*\*Add file > Create new file\*\*, en le nommant `semaine-1.md`.



###### \*\*2. Installation de GitHub Desktop\*\*

\- J'ai téléchargé l'application sur desktop.github.com (Download for Windows) et je l'ai installée.

\- Je me suis connectée avec \*\*Sign in to GitHub.com\*\*, puis j'ai cliqué sur \*\*Authorize desktop\*\* dans mon navigateur.

\- Sur l'écran \*\*Configure Git\*\*, j'ai cliqué sur \*\*Finish\*\*.



###### \*\*3. Récupération de mon repo sur mon PC (cloner)\*\*

\- Dans \*\*Your repositories\*\*, j'ai sélectionné `belgracezannou-commits/learning-journal`, puis j'ai cliqué sur \*\*Clone\*\*.

\- Le dossier est maintenant sur mon ordinateur, dans `Documents\\\\GitHub\\\\learning-journal`.

\- \*\*Show in Explorer\*\* me permet de l'ouvrir directement.



###### \*\*4. Le cycle que je vais répéter à chaque fois\*\*

1\. Je modifie un fichier et j'enregistre (Ctrl + S).

2\. Dans GitHub Desktop, j'écris un message dans \*\*Summary\*\*.

3\. Je clique sur \*\*Commit to main\*\*.

4\. Je clique sur \*\*Push origin\*\* pour envoyer mes modifications en ligne.
